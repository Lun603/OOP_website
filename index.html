🌿 2. Git (MINGW64) & Terminal 實用指令寶典

🎓 課堂重點：Git 控制版本的三大核心區域觀念

1. 工作區 (Working Directory)：實際編輯檔案處。 2. 暫存區 (Staging Area)：git add 準備檔案處。 3. 儲存區 (Repository)：git commit 正式打包紀錄處。

建構與版本提交指令：

git init

在當前目錄建立隱藏的 .git 版本資料夾。

git status

檢視狀態：🔴 紅色為未暫存修改，🟢 綠色為已進入暫存區。

git add .

將當前目錄下所有修改過的檔案送進暫存區。

git commit -m "備註"

將暫存區內容正式提交成版本，並附上說明訊息。

歷史、重置與分支管理指令：

git log --oneline

精簡顯示過往所有的 commit 歷史紀錄與 ID 前 7 碼。

git diff

比較「工作區」與「暫存區」之間程式碼的詳細修改差異。

git switch -c <分支名>

建立並切換至新開發分支，實現獨立功能開發。

git push origin main

推送本地儲存區程式碼覆蓋至 GitHub 遠端儲存庫。

🔬 4. 高階 OOP 與記憶體細節解析

1. Stack vs Heap 記憶體配置 (物件生命週期)

  • Book b("C++", 101);：配置於 Stack，離開作用域自動呼叫解構子銷毀。
  • Book* b = new Book("C++", 101);：配置於 Heap，必須手動 delete b; 釋放記憶體。

2. RAII (Resource Acquisition Is Initialization)

將資源（動態記憶體）綁定至 Stack 物件生命週期，宣告時獲取資源，離開時自動解構歸還，std::vector<Book> 即完美運用 RAII。

3. std::sort 比較邏輯 (a, b)

Lambda 回傳 a.getID() < b.getID() 時：當 a 比 b 小回傳 true 放在前面 → 升冪排序 (小到大)。

💡 5. C vs C++ OOP 對照表

概念 C 語言做法 C++ 物件導向做法
資料封裝 struct 成員全公開，外部可自由修改 使用 private 保護成員，僅透過 Getter 存取
初始化 手動呼叫 init(&b)，忘記會讀到垃圾值 建構子 自動觸發，確保誕生時資料有效
資源回收 手動 free()，容易記憶體洩漏 解構子 (RAII) 在離開作用域時自動回收
動態陣列 手動 malloc() + realloc() 管理長度 使用 std::vector，自動伸縮記憶體並維護生命週期
