🌿 4. Git (MINGW64) & Terminal 實用指令寶典

🎓 課堂重點：Git 控制版本的三大核心區域觀念

1. 工作區 (Working Directory)：實際編輯檔案處。 2. 暫存區 (Staging Area)：git add 準備檔案處。 3. 儲存區 (Repository)：git commit 正式打包紀錄處。

git init

在當前目錄建立隱藏的 .git 版本資料夾。

git status

檢視狀態：🔴 紅色為未暫存修改，🟢 綠色為已進入暫存區。

git add .

將當前目錄下所有修改過的檔案送進暫存區。

git commit -m "備註"

將暫存區內容正式提交成版本，並附上說明訊息。

進階分支與遠端協作指令：

git pull origin main

將遠端 GitHub 上的最新程式碼拉取下載並自動合併至本地。

git fetch

查看遠端庫有哪些新更新，但先不自動合併進本地檔案。

git switch -c feature-branch

建立獨立的開發分支，避免直接影響主線 main 程式碼。

git stash / git stash pop

暫存未完成的修改，切換分支修復緊急 Bug 後再還原。

🔬 6. 高階 OOP 與微架構解析

1. Stack vs Heap 記憶體配置 (與計算機組織的對應)

  • Book b("C++", 101);：配置於 Stack，由 CPU 暫存器 (RSP/RBP) 直接維護位址，離場自動銷毀。
  • Book* b = new Book("C++", 101);：配置於 Heap，屬於 OS 虛擬記憶體區塊，需透過 delete 歸還，否則造成 Memory Leak。

2. 計算機組織預備觀念：C++ 編譯後如何執行？

C++ 原始碼經過 GCC/Clang 編譯器翻譯成 Assembly (組合語言)，最終生成二進位機器碼 (0101)。CPU 的控制單元 (Control Unit) 會從 RAM 擷取指令 (Fetch)，解碼 (Decode) 後丟給算術邏輯單元 (ALU) 執行排序與比對計算。

3. std::sort 比較邏輯 (a, b)

Lambda 回傳 a.getID() < b.getID() 時：當 a 比 b 小回傳 true 放在前面 → 升冪排序 (小到大)。

💡 7. C vs C++ OOP 對照表

概念 C 語言做法 C++ 物件導向做法
資料封裝 struct 成員全公開，外部可自由修改 使用 private 保護成員，僅透過 Getter 存取
初始化 手動呼叫 init(&b)，忘記會讀到垃圾值 建構子 自動觸發，確保誕生時資料有效
資源回收 手動 free()，容易記憶體洩漏 解構子 (RAII) 在離開作用域時自動回收
動態陣列 手動 malloc() + realloc() 管理長度 使用 std::vector，自動伸縮記憶體並維護生命週期
